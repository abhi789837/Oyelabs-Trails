## Facts verified
- Versions (`npm view`, 2026-09-21): `@apollo/client` latest 4.3.1, `@apollo/server` latest 5.5.1, `dataloader` 2.2.3.
- Apollo Server 5 (migration guide): Node.js 20+, graphql 16.11.0+, Express integration moved to `@as-integrations/express4`/`express5`, `status400ForVariableCoercionErrors` now defaults to true, `startStandaloneServer` no longer uses Express, Apollo Server 4 end of life 2026-01-26. CORS/CSRF page: standalone server's CORS is a fixed `*`, credentials need explicit origins, CSRF prevention requires a preflight-forcing header such as `Apollo-Require-Preflight` for GET and multipart requests.
- Apollo Client 4 (migration guide): hooks from `@apollo/client/react`, `rxjs` peer dependency, explicit `HttpLink` (the `uri`/`credentials` constructor shortcuts were removed), `ApolloError` removed in favour of `CombinedGraphQLErrors`, `ServerError`, etc., network errors now follow `errorPolicy`, GraphQL-over-HTTP `Accept` header.
- Cache behaviour used by the challenge (caching overview, cache configuration, mutations, optimistic UI): cache ID is `__typename` plus `id` or `_id`; objects without an ID are stored inside their parent; incoming fields overwrite shared fields and other fields are kept; references use `{ "__ref": "Type:id" }`; a created object isn't added to list fields automatically (`update` with `cache.modify`/`writeFragment`); `update` runs twice with an optimistic response; optimistic data lives in a separate layer and is discarded on error; mutations only support `network-only` and `no-cache` fetch policies; `errorPolicy` `none` (default) discards partial data, `all` keeps it. Per the garbage-collection page, the default read function for list fields filters out dangling references automatically, while a single dangling reference needs a custom read function; the challenge models this as "skip in lists, miss for single fields".
- GraphQL spec (September 2025 edition, spec.graphql.org): OneOf input objects and `@oneOf`; execution errors on non-null positions propagate to the parent response position.
- graphql.org Learn pages (performance, security) cover N+1/DataLoader, depth and complexity limits, and persisted operations; the DataLoader README says instances are typically created per request and warns that sharing one can leak cached data between requests.
- The schema-evolution classifications (output `String` to `String!` safe, the reverse breaking; optional to required argument breaking) follow from the spec's validation and coercion rules rather than from a single doc page; a human may want to double-check the wording against their schema-check tool.
- The cache challenge's 11 expectations were written by hand and then run against the reference solution; the untouched starter fails all 11.
