## Facts verified
- OWASP API Security Top 10: 2023 is still the latest edition (api-security.owasp.org lists only 2019 and 2023). Release notes: Excessive Data Exposure + Mass Assignment merged into API3 BOPLA; new API6 business flows and API10 unsafe consumption; SSRF is API7; Injection and Insufficient Logging dropped. OWASP Top 10:2025 (separate list) per the content guide.
- Password storage (OWASP cheat sheet, fetched): Argon2id m=19 MiB t=2 p=1 (and equivalent combos), scrypt N=2^17 r=8 p=1, bcrypt cost >= 10 and legacy-only, 72-byte limit, pre-hash null-byte and password-shucking warning with the `bcrypt(base64(hmac-sha384(pw, pepper)))` recommendation, PBKDF2-HMAC-SHA256 600,000 iterations for FIPS. Pepper stored outside the DB; rotating it forces resets.
- bcrypt 72-byte behavior per library: node.bcrypt.js README says bytes beyond 72 are ignored; pyca/bcrypt 5.0 changelog says `hashpw` now raises `ValueError` over 72 bytes; Go `x/crypto/bcrypt` returns `ErrPasswordTooLong`. The quiz names Node's `bcrypt` explicitly for that reason.
- NIST SP 800-63B-4 (pages.nist.gov): 15-character minimum for single-factor passwords (8 with MFA), permit at least 64, no composition rules, no periodic change, blocklist required, salt >= 32 bits, no truncation, <= 100 consecutive failures.
- RFC 9700 (Jan 2025): exact redirect URI matching; PKCE MUST for public clients, RECOMMENDED for confidential; S256 the only method not exposing the verifier; implicit SHOULD NOT; ROPC MUST NOT; refresh tokens for public clients sender-constrained or rotated (Section 4.14.2 wording on family revocation quoted in the rotation quiz).
- OAuth 2.1: `draft-ietf-oauth-v2-1-16`, updated 2026-09-02, still a WG draft. Differences list: PKCE by default, implicit and ROPC omitted, exact redirect matching, no bearer tokens in query strings, one-time or sender-constrained public-client refresh tokens, PKCE `plain` removed.
- RFC 10017: BFF "strongly recommended for business applications, sensitive applications, and applications that handle personal data".
- OIDC Core: `aud` must contain the client_id; nonce must be checked; code-flow clients MAY use TLS to the token endpoint instead of checking the ID token signature (reflected in quiz wording).
- RFC 7519: current time must be before `exp`, at or after `nbf`, "small leeway" allowed; `aud` may be a string or array. RFC 8725: libraries must let callers fix the allowed algorithms; `none` and RS256-to-HS256 confusion described. The JWT challenge's boundary rules (`now >= exp + leeway` expired, `now + leeway < nbf` not yet valid) follow these.
- Auth0 rotation docs: reuse of an invalidated token revokes the whole token family.
- CORS (MDN guide and header pages, Fetch standard): safelisted methods and headers; the three safelisted `Content-Type` values; wildcards are literal with credentials; `Authorization` is never covered by `Access-Control-Allow-Headers: *`; Max-Age default 5 s, Chromium cap 7200 s, Firefox cap 86400 s; preflight needs an ok (2xx) status and never carries credentials; `Vary: Origin` guidance.
- Rate limiting: IETF `draft-ietf-httpapi-ratelimit-headers-11` (updated 2026-05-23, still a draft) defines `RateLimit-Policy` and `RateLimit`. Cloudflare's sliding-window-counter post. The token-bucket challenge's 11 expected outputs were computed by hand and confirmed against the reference solution (all values chosen to be exact in binary floating point).
- Challenges: all expected values were written by hand first, then run against the reference solutions in a scratch harness mirroring the in-app worker, then through `npm run content:check`.
