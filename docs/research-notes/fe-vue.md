## Code challenges
- Each was also run against typical wrong implementations, which fail the intended tests: reactivity (no dependency cleanup, `activeEffect = null` instead of a stack, no `Object.is` check, no array `length` trigger, self-triggering effect); scheduler (no mid-flush insertion guard, no post-flush dedupe, never clearing the "waiting" flag, no re-flush after post-flush callbacks); router (definition-order matching, `beforeEnter` on every navigation, both naive prefix tie-breaks); store (starter only).
- Simplifications to flag: the scheduler challenge models Vue's `queueJob`/`queuePostFlushCb`/`nextTick` with a fake microtask queue (`nextTick` that always defers is equivalent in this model and passes). The router challenge's numeric scores are simplified from Vue Router's path ranker, but the outcomes tested match real Vue Router 5.3.1 (the prefix tie-break mirrors `comparePathParserScore`). The store challenge notifies synchronously (like `$subscribe(cb, { flush: 'sync' })`) and recomputes getters on read; both differences are stated in the instructions.
