## Facts verified
- Next.js 16.3.5 is `latest` on npm (16.0.0 released 2025-10-22, 16.3.0 on 2026-08-03). `next-auth`: `latest` = 4.24.15, `beta` = 5.0.0-beta.32 (2026-07-20). Checked with the npm registry.
- Auth.js joined Better Auth: authjs.dev banner ("The Auth.js project is now part of Better Auth") and the Better Auth announcement (Sep 22, 2025: security patches continue, Better Auth recommended for new projects). Auth.js v5 install `next-auth@beta`, `auth.ts` exports `{ handlers, signIn, signOut, auth }`, route `app/api/auth/[...nextauth]/route.ts`, `export { auth as proxy }` for Next.js 16, `AUTH_SECRET` (authjs.dev installation page). JWT default without adapter, ~4 KB cookie limit with chunking, JWTs can't be expired early without a blocklist (authjs.dev session strategies). "You should not rely on the proxy exclusively for authorization" (authjs.dev protecting resources).
- Upgrade guide v16: sync `params`/`searchParams`/`cookies()`/`headers()` removed; `middleware` → `proxy` (Node.js runtime, not configurable; keep `middleware.ts` only for Edge); `revalidateTag` needs a second argument (one-arg form deprecated); `updateTag` (Server Actions only) and `refresh`; `cacheLife`/`cacheTag` stable; PPR via `cacheComponents`; parallel slots require `default.js`; `next/image` defaults (`qualities: [75]`, `minimumCacheTTL` 4 h, `imageSizes` without 16, local query strings need `localPatterns`, `maximumRedirects` 3); `images.domains` deprecated.
- Edge runtime: route-segment `runtime` docs mark `'edge'` deprecated ("Remove the runtime export"); `proxy.js` docs: setting `runtime` in Proxy throws. Vercel's Edge runtime page: "We recommend migrating from edge to Node.js" and "Starting in Next.js 16.3, setting runtime = 'edge' is no longer supported" (Vercel's wording; the Next.js docs say deprecated, so the module says "deprecated").
- Cache Components: `cacheLife` presets table and `stale`/`revalidate`/`expire` semantics; custom and inline profiles inherit from `default`; short-lived thresholds (`revalidate: 0`, `expire` < 5 min, `stale` < 30 s) exclude from prerenders; nested cache without explicit `cacheLife` errors; cache keys include build ID; runtime `use cache` in-memory per instance on serverless; `use cache` can't read `cookies()`/`headers()`/`searchParams` (all from the `use cache`, `cacheLife` and caching docs). `revalidateTag` semantics: profile `max` = one-year stale window, `{ expire: 0 }` immediate, one-arg behaves like `{ expire: 0 }`, revalidation triggered by the next request, tags case-sensitive, ≤ 256 chars (revalidateTag docs). These drive the caching simulator; it deliberately models only the server side.
- Previous model: `fetch` not cached by default, but a `fetch` with no `cache` option reachable before any request-time API "is fetched once during next build" because the route is prerendered (caching-without-cache-components guide). `dynamicParams` not available with Cache Components; empty `generateStaticParams` is a build error with Cache Components.
- Server Actions: POST-only, public endpoints ("Always verify authentication and authorization inside every Server Function"); single-round-trip re-render for `updateTag`/`revalidatePath`/`refresh`/cookie mutation/`redirect` but not SWR `revalidateTag`; sequential client dispatch; Origin/Host check, 1 MB body limit, encrypted IDs and closure variables, `NEXT_SERVER_ACTIONS_ENCRYPTION_KEY` for multi-instance (server-actions guide, data-security guide). `redirect` throws (call outside `try/catch`), 303 for progressive-enhancement submissions (redirect docs). `useActionState` action signature `(prevState, formData)` (forms guide).
- Proxy: matcher-less Proxy runs on `_next/static`, `_next/image` and public assets; execution order (config headers, redirects, Proxy, beforeFiles, filesystem, afterFiles, dynamic routes, fallback); Server Functions are POSTs to the page route so matcher exclusions skip them; fetch cache options have no effect in Proxy; `NextResponse.next({ request: { headers } })` vs `{ headers }` (proxy.js reference). CVE-2025-29927 details from the Vercel postmortem (`x-middleware-subrequest`, fixed 15.2.3 / 14.2.25, self-hosted only).
- Routing precedence and the challenge rules: Next.js source at tag v16.3.5, `packages/next/src/shared/lib/router/utils/sorted-routes.ts` (node itself, then static children alphabetically, then `[slug]`, `[...slug]`, `[[...slug]]`; errors for mixed required/optional catch-alls and for a route plus an optional catch-all at the same level, which the fixture avoids). Route groups conflicting at one path and `page` + `route` in one segment are documented build errors.
- Metadata merge and title rules: generateMetadata docs (shallow merge, `openGraph` replaced/inherited examples, template applies to children only, `absolute`) plus the Next.js source at v16.3.5 (`lib/metadata/resolve-metadata.ts` `accumulateMetadata`: the stash updates after every item except the last two; `resolvers/resolve-title.ts`: string titles carry no template, so an intermediate plain-string title clears the stash; `inheritFromMetadata` fills `openGraph.title`/`description`). The challenge simplifies `openGraph.title` to a plain string (no OG title templates).
- Streaming contract: status committed with the first chunk, `notFound()` mid-stream gives 200 + `noindex`, late `redirect()` becomes client-side (streaming guide). Crawlers skip the static shell and get a full request-time render (caching docs, "Bots and crawlers"). Streaming metadata disabled for HTML-limited bots (generateMetadata docs).
- Images/fonts: `sizes` behaviour, `preload` replaces deprecated `priority`, docs recommend `loading="eager"`/`fetchPriority="high"` in most cases, formats/Accept negotiation, blurDataURL automatic only for static imports (Image docs). Font: build-time self-hosting, `display: 'swap'` default, `adjustFontFallback`, per-route preloading, each loader call is its own instance (Font docs).
- Deployment: env var changes only apply to new deployments; Preview variables per branch (Vercel env docs); Fluid compute default for new projects since 2025-04-23, in-function concurrency shares one instance (Vercel Fluid compute docs); functions default to `iad1` (Vercel runtimes docs); Standard Protection covers all URLs except production domains (Vercel Deployment Protection docs). `output: "standalone"` doesn't copy `public/` or `.next/static` (output docs); static export unsupported features list (static-exports guide); multi-instance cache handler, encryption key, `deploymentId`, nginx `X-Accel-Buffering: no` (self-hosting guide).
- Code challenges were run against typical wrong implementations (no precedence sort, "most static segments" sort, not skipping private/slot/intercepting folders, treating slots as groups, stripping interception markers, no decoding, optional catch-all returning `[]`, catch-all accepting zero segments, no conflict check; SWR-only or expire-only tag invalidation, no `updateTag` context check, blocking stale reads, no background refresh, ignoring `expire`, case-insensitive tags, custom profiles not inheriting an overridden `default`, fetching before resolving the profile; templates applied to the page's own segment, chained templates, deep-merged objects, no `openGraph` fill, mutating inputs, `null` for template-only titles). Each fails at least one test.
