## Facts verified
- Build cache: `COPY`/`ADD` cache checksums use file metadata but not mtime; `RUN` matches on the command string; a miss invalidates the rest of the stage; secret contents don't affect the cache, build args do (docs `build/cache/invalidation.md`). A changed `ARG` misses at first use, and every `RUN` after the `ARG` uses it implicitly (Dockerfile reference, "Impact on build caching"). Build args are visible in `docker history` and max-mode provenance.
- `.dockerignore`: patterns relative to the context root, `**` for any depth, last matching line wins, `!` re-includes; `*.md` doesn't match subdirectories (docs `build/concepts/context.md`). The code challenge's `.dockerignore` and source matching follow these rules in simplified form (stated in the instructions).
- BuildKit builds only the stages the target depends on; the legacy builder built every stage up to the target (docs `multi-stage.md`).
- `ADD` auto-extracts local tar archives but not remote ones unless `--unpack` (Dockerfile reference). Shell-form `ENTRYPOINT` runs under `/bin/sh -c`, which doesn't pass signals (reference).
- `docker stop`: SIGTERM (or `STOPSIGNAL`), then SIGKILL after the grace period; the daemon default is 10 s for Linux containers, 30 s for Windows (docker/cli `container_stop.md`). `--init` runs an init that forwards signals and reaps processes (`container_run.md`).
- PID 1 only receives signals it has handlers for; SIGKILL/SIGSTOP from an ancestor namespace are forced; when PID 1 exits the kernel SIGKILLs the rest of the namespace (man7 `pid_namespaces(7)`).
- OverlayFS copy-up copies whole files, not blocks (docs `overlayfs-driver.md`).
- Volumes: empty volumes are pre-populated from the image path, non-empty volumes and bind mounts obscure it; volumes live under `/var/lib/docker/volumes`; tmpfs counts against the memory cgroup (docs `volumes.md`, `bind-mounts.md`, `tmpfs.md`). Embedded DNS at `127.0.0.11`; default bridge has no name resolution (network docs). Published ports bind `0.0.0.0` and `[::]` by default and Docker's rules divert traffic before ufw (`port-publishing.md`, `packet-filtering-firewalls.md`).
- Compose: `version` is obsolete and only warns; `depends_on` conditions `service_started`/`service_healthy`/`service_completed_successfully`, `restart` (2.17.0), `required: false` (2.20.0); targeting a service enables its profiles but not its dependencies' (docs `startup-order.md`, `services.md`, `profiles.md`, `version-and-name.md`).
- CI: cache `mode=min` is the default and exports only final-image layers, `mode=max` all stages (`cache/backends`); min-level provenance attestations are added by default, SBOM with `--sbom=true` (`metadata/attestations`).
- Alpine/musl: 128 KB default thread stack vs 2–10 MB on glibc (musl wiki); musl wheels (PEP 656) now common but not universal (pythonspeed, updated Jan 2026). Distroless: no shell, exec-form entrypoints required, `nodejs24-debian13` image with `node` entrypoint, `:debug` and `nonroot` tags (distroless README).
- Kubernetes: `maxSurge` rounds up and `maxUnavailable` rounds down, both default 25%; rollouts trigger only on Pod template changes; a stalled rollout only reports `ProgressDeadlineExceeded` (default 600 s); Secrets are stored unencrypted in etcd by default and readable by anyone who can create Pods in the namespace; CPU limits throttle, memory limits OOM-kill (`OOMKilled`); liveness doesn't wait for readiness; failing readiness removes the Pod from EndpointSlices; NodePort range 30000–32767; LoadBalancer allocates node ports by default; ExternalName is a CNAME; ConfigMap env vars need a Pod restart (kubernetes/website sources).
