## Facts verified
Scratch project: `@nestjs/core` 12.0.3, `@nestjs/common` 12.0.4, `@nestjs/microservices` 12.0.4, class-validator 0.15.1, class-transformer 0.5.1, rxjs 7.8.2, Node 24.
- NestJS 12 (migration guide source): ESM-only packages, Node 20.19+/22.12+ to run a CommonJS app, lifecycle hooks ordered by hierarchy level, `@Optional()` no longer inherited, opt-in `routeConflictPolicy`/`routeResolutionStrategy`, `errorCode` in `HttpExceptionOptions`, `StandardSchemaValidationPipe`, `errorFormat: 'grouped'`, NATS v3, Kafka regex patterns.
- Modules (run): unexported provider gives `UnknownDependenciesException` at bootstrap; the same class in two modules gives two instances; `@Global()` still needs `exports` and one import; dynamic-module metadata extends the static metadata; re-exporting works; module classes can't be injected; `forwardRef` on both sides resolves; factory cycle gives `CircularDependencyException`; an `undefined` param type gives `UndefinedDependencyException` ("...the argument at index [0] is available in the current module", with an `import type` hint).
- Providers (run): request scope bubbles to consumers; `app.get()` on scoped providers throws `InvalidClassScopeException`; `resolve()` with one `ContextId` returns one instance; a transient provider is per consumer (a consumer listing it twice gets the same instance); the last provider with a token wins; falsy `useValue` works; a singleton factory runs once; async factories are awaited.
- Controllers (run): `@Res()` without passthrough never responds (aborted after 800 ms); passthrough sets the header and sends the value; POST 201, `@HttpCode(200)`; `@Param('id') id: number` stays `"42"`; `:id` declared first shadows `me` on Express and `routeResolutionStrategy: 'specificity'` fixes it; `of(1, 2, 3)` sends `3`; `@Redirect` defaults to 302 and a returned object overrides it.
- Validation (run): default messages (the challenge uses them verbatim), messages reported in reverse decorator order, `whitelist` strips undecorated props, `forbidNonWhitelisted` alone does nothing, forbidden-property messages come first, `transform` converts params and creates instances, `@IsInt` on query `"2"` fails without implicit conversion, implicit conversion turns `"false"` into `true`, `""` into `0` and `5` into `"5"`, `NaN` fails `@IsNumber`, an `Object` metatype (interface) skips validation, nested objects aren't validated without `@ValidateNested`.
- Lifecycle (run): middleware, guards, interceptors (pre), pipes, handler, interceptors (post, route to global), filters; a guard denial becomes 403 and is caught by a route filter; pipe errors reach an interceptor's `catchError`; middleware exceptions reach only global filters; a plain `Error` skips a `@Catch(HttpException)` route filter; default 500 body; within one `@UseFilters(A, B)` list (and `useGlobalFilters`) the last-declared filter is tried first. These are the rules the lifecycle challenge encodes.
- Interceptors (run): the timeout interceptor answers 408 while the handler keeps running; `tap(fn)` doesn't fire on errors (the docs' prose says it fires "upon graceful or exceptional termination", which is imprecise); `map` works with passthrough.
- Reflector (run): `get(Roles, handler)` misses class metadata; `getAllAndOverride` returns the first defined value in target order; `getAllAndMerge` returned `['admin', 'user']` although the docs example says `['user', 'admin']`, so the quiz doesn't assert merge order.
- `ClassSerializerInterceptor` (run): `{ user: new UserEntity() }` does exclude `@Exclude()` fields in this version, contrary to the docs warning, so the quiz uses a plain `{ ...row }` object as the leaking case.
- Microservices (docs source): `send()` cold and `emit()` hot, lazy `ClientProxy` connection, Redis transport fire-and-forget, `inheritAppConfig`, `startAllMicroservices()` before `listen()` warning, Kafka reply topics and partitions, retriable exceptions, `RpcException` body, event-handler filter warning. Prisma 7 recipe (`prisma-client` generator, `output`, driver adapters, `moduleFormat = "cjs"`) and TypeORM `synchronize`/`autoLoadEntities`/re-export notes also from the docs source.
