## Facts verified
- React Router 8.4.0 is current; v8.0.0 released 2026-06-17 (CHANGELOG): requires Node 22.22+, React 19.2.7+, Vite 7+; removes `react-router-dom` (import from `react-router`, `RouterProvider` from `react-router/dom`); middleware always enabled (stabilized in 7.9.0).
- Route ranking copied from `packages/react-router/lib/router/utils.ts` (`computeScore`: static 10, dynamic 3, index +2, splat −2, siblings tie by order); static segments case-insensitive by default; splat matches zero segments; malformed percent-encoding kept raw (`decodePath`); all matches share one params object (parent `useParams` sees child params). The challenge solution was diffed against real `matchRoutes` from react-router 8.4.0 on every test URL.
- Loaders run in parallel ("How-To: Data Strategy"); revalidation defaults, 4xx/5xx submissions not revalidating, and data-mode revalidation on param/search-param changes ("Revalidation Optimization"); fetcher self-cancellation ("Race Conditions"); server middleware only runs on client navigations that make a `.data` request ("Middleware: When Middleware Runs"); absolute cross-origin redirects become document navigations (`startRedirectNavigation` in router.ts).
- Redux Toolkit 2.12 / Redux 5: Immer "mutate or return, not both" (reproduced: `(state) => (state.items = [])` throws; `state = initialState` is a no-op); serializability middleware logs via `console.error` (source + reproduced), dev-only; `createAsyncThunk` promise always resolves, `.unwrap()` throws (docs + reproduced); RTK 2 removed object syntax for `extraReducers`; RTK Query refetches subscribed and removes unsubscribed invalidated data (automated-refetching docs); react-redux dev `stabilityCheck`.
- Zustand 5.0.15: v5 migration guide ("Requiring stable selector outputs", Maximum update depth, `useShallow`, persist no longer stores initial state); persist default `createJSONStorage(() => localStorage)`, version mismatch without `migrate` discards stored state; Next.js guide ("no global stores", per-request store).
- TanStack Query 5.103.1: Important Defaults (staleTime 0, gcTime 5 min, refetch on mount/focus/reconnect, `staleTime: 'static'`), Migrating to v5 (`cacheTime`→`gcTime`, `loading`→`pending`, `isLoading = isPending && isFetching`, `onSuccess` removed from queries), `hashKey`/`partialMatchKey` source. The challenge solution was run against `@tanstack/query-core` 5.x with a fake clock on all 15 scenarios (dedupe, prefix/partial invalidation, gc during fetch, `cancelRefetch` only when data exists) with identical results.
- React Hook Form 7.88 (v8 in beta): `mode` default `onSubmit`, `reValidateMode` default `onChange` (useForm docs); the challenge's timing rules are ported from RHF's `skipValidation.ts`; `deps` triggers dependent validation (`createFormControl.ts`); built-in `required` doesn't trim. Formik: 2.4.6 (Apr 2024), 2.4.8/2.4.9 (Nov 2025), 842 open issues, no pushes since (npm + GitHub API, 2026-09-21).
- Vitest 5.0.1 (released 2026-09-03), RTL 16.3.3, user-event 14.6.7 (`advanceTimers` option, fireEvent vs user-event docs), `findBy` = `getBy` + `waitFor`.
- Playwright 1.63: actionability checks and 5 s assertion timeout (docs); Cypress 16.1: 4 s `defaultCommandTimeout`, no driving two browsers, multi-tab via `@cypress/puppeteer`, `cy.origin` (trade-offs docs).
- Code challenges were also run against typical wrong implementations (first-match routing, case-sensitive matching, no index bonus, unsorted key hashing, no dedupe, refetching inactive queries, gc removing mid-fetch queries, never cancelling refetches, blur validation after submit, ignoring `deps`, untrimmed `required`); each fails at least one test.
