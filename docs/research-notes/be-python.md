## Facts verified
Scratch venv: Python 3.14.6, pydantic 2.13.5, FastAPI 0.141.1, Django 6.1.1, DRF 3.18.1, Celery 5.6.3.
- Pydantic (run): full lax/strict matrix for int/float/str/bool. All 19 `py-fastapi-pydantic` expectations were regenerated independently from real Pydantic models (`create_model` + `model_validate`): 0 mismatches. A 496-case scalar fuzz of the reference solution against Pydantic differs only in the two documented simplifications (underscores in float strings; `1e20` sent to a bool). Also: `Optional[int]` without a default is required, defaults aren't validated, errors come in field order then `extra_forbidden`, non-dict input gives `model_type`.
- Django ORM (run): all 16 `py-django-orm` scenarios replayed on Django 6.1.1 (SQLite, `CaptureQueriesContext`, per-step query labels): 0 mismatches. Also: `if qs:` evaluates (2 queries with a prefetch); `FETCH_PEERS` fixes the FK N+1 (2 queries) but not M2M `.all()` (still 4); `FETCH_RAISE` raises `FieldFetchBlocked`; `update()` and `bulk_create()` send no `post_save`; `on_commit` callbacks are dropped on rollback; Django 6.x refreshes fields assigned `F()` expressions after `save()`, so the quiz avoids the old `CombinedExpression` gotcha; async QuerySet methods wrap sync calls in `sync_to_async` (source).
- Django releases (release notes): 6.0 (Dec 2025) CSP, template partials, Tasks framework without a worker, `DEFAULT_AUTO_FIELD` now `BigAutoField`; 6.1 (Aug 2026) fetch modes, DB-level `on_delete`, `MAILERS`, deprecation of `list_select_related = True` and argument-less `select_related()`, calendar versioning announced.
- Templates and views (run): auto-escaping, dict-key-first dotted lookup (`{{ d.items }}`), missing variables render `''`, CSRF 403 on POST without a token (`Client(enforce_csrf_checks=True)`), a class-attribute list shared across CBV requests; `AuthenticationMiddleware` raises `ImproperlyConfigured` when placed before `SessionMiddleware` (source).
- DRF (run and docs): `save()` before `is_valid()` asserts; router patterns and names for detail and list actions; nested writes assert; defaults `AllowAny`, no pagination class or page size, no throttles. From the docs: `has_object_permission()` only via `get_object()`, throttling isn't a security measure and uses non-atomic cache operations, cursor pagination needs a unique unchanging ordering (default `-created`), built-in OpenAPI generation deprecated in favour of drf-spectacular.
- FastAPI (run): `async def` + `time.sleep` serializes (0.91 s for 3 × 0.3 s) while `def` runs in the threadpool (0.35 s); AnyIO's default limiter is 40 (50 × 0.2 s took 0.43 s, 40 took 0.24 s); per-request dependency cache; `response_model` and return annotations filter output; POST defaults to 200; 422 `loc` `['body', 'password']`; yield-dependency exit code runs after the response (after background tasks in 0.141.1); a swallowed exception gives a 500. From the docs source: `lifespan` disables `on_event`, `Depends(scope="function")` added in 0.121.0, 0.118.0 restored exit-after-response.
- Celery (source and docs): `max_retries` 3, `default_retry_delay` 180 s, `retry_backoff` factor 1 (1, 2, 4 s), `retry_backoff_max` 600, `retry_jitter` default True using full jitter `randrange(countdown + 1)`, `acks_late` default False, `worker_prefetch_multiplier` 4, Redis `visibility_timeout` 3600 (kombu), `delay_on_commit()` in `celery.contrib.django.task`, one beat scheduler per schedule, `-B` not for production.
- Python (run on 3.14.6): every `py-essentials` snippet (mutable default, dataclass `ValueError` text, generator exhaustion, context-manager rollback, `gather` order and 0.3 s timing, `gather` not cancelling siblings vs `TaskGroup` cancelling, `to_thread`). Free-threaded build officially supported in 3.14 with a 5–10% single-thread penalty and PEP 649 lazy annotations (What's New in 3.14); `asyncio.gather`/`TaskGroup`/`create_task` semantics (asyncio docs); uv lock/sync and `--locked` (docs.astral.sh).
